\section{Memeriksa Memori, Stack, dan Memperbaiki Hang}
\label{sec:dump-stack}

Kesalahan logika tidak selalu terlihat dari register. Kadang nilai
yang salah tersimpan di memori, atau stack berisi susunan yang tidak
sesuai. Untuk kasus seperti itu, isi memori dan stack harus diperiksa
langsung.

\subsection{Memeriksa Memori dengan Dump}

Perintah \file{D} pada DEBUG menampilkan isi memori dalam bentuk
heksadesimal. Bentuk penulisannya:

\begin{lstlisting}[language=MASM, numbers=none]
D DS:0000           ; tampilkan awal segmen data
D DS:0010 L 20      ; tampilkan 20h byte mulai offset 0010h
D SS:SP             ; tampilkan stack pada puncak saat ini
\end{lstlisting}

Nilai \reg{DS} harus dibaca lebih dahulu dengan perintah \file{R}.
Alamat yang tampil pada \file{D} adalah pasangan segmen dan offset,
bukan alamat fisik.

\subsection{Contoh: Stack Tidak Seimbang}

Program \file{bug-stack.asm} memanggil prosedur \code{HITUNG}.
Prosedur mendorong tiga register dengan \asm{PUSH}, tetapi hanya
memulihkan dua dengan \asm{POP}.

\begin{lstlisting}[language=MASM, numbers=none]
HITUNG PROC
    PUSH AX
    PUSH BX
    PUSH CX
    ; ... isi prosedur ...
    POP CX
    POP BX
    ; POP AX tidak ada
    RET
HITUNG ENDP
\end{lstlisting}

Akibatnya, saat \asm{RET} dijalankan, puncak stack berisi nilai
\reg{AX} lama, bukan alamat kembali. Prosesor melompat ke alamat yang
salah dan program berhenti.

Tabel~\ref{tab:trace-bug-stack} memperlihatkan susunan stack sebelum
dan sesudah kesalahan.

\begin{table}[H]
    \centering
    \caption{Susunan stack pada \file{bug-stack.asm}.}
    \label{tab:trace-bug-stack}
    \small
    \begin{tabular}{@{}p{4.2cm}p{4.0cm}p{4.8cm}@{}}
        \toprule
        \textbf{Tahap} & \textbf{Isi puncak stack} &
        \textbf{Keterangan} \\

Perbaikan dilakukan dengan menambahkan \lstasm|POP AX| sebelum
\asm{RET}, sehingga jumlah \asm{PUSH} dan \asm{POP} seimbang. Versi
perbaikan tersedia pada \file{bug-stack-fix.asm}.

\subsection{Memeriksa Stack Frame}

Bila prosedur memakai \reg{BP}, isi stack frame dapat diperiksa
dengan \file{D SS:BP}. Susunan yang diharapkan:

\begin{itemize}
    \item \code{[BP+0]}: nilai \reg{BP} lama;
    \item \code{[BP+2]}: alamat kembali;
    \item \code{[BP+4]}: parameter pertama;
    \item \code{[BP+6]}: parameter kedua.
\end{itemize}

Bila susunan ini tidak sesuai, kemungkinan ada parameter yang salah
urut, jumlah \asm{PUSH} yang tidak seimbang, atau \reg{SP} berubah
tanpa disengaja.

\subsection{Analisis Program yang Berhenti}

Urutan pemeriksaan program yang berhenti:

\begin{enumerate}
    \item periksa apakah perulangan memiliki syarat berhenti yang
          benar;
    \item periksa nilai pencacah pada setiap iterasi;
    \item periksa keseimbangan \asm{PUSH} dan \asm{POP};
    \item periksa isi stack pada saat \asm{CALL} dan \asm{RET};
    \item periksa apakah program pernah mencapai instruksi keluar
          \code{INT 21h} fungsi \hex{4C}.
\end{enumerate}

\begin{peringatanbox}
\vspace{1.1em}
Program yang berhenti belum tentu kesalahan prosesor. Sering kali
program hanya terjebak pada perulangan yang syaratnya tidak pernah
terpenuhi. Periksa nilai pencacah dan \eng{flag} sebelum menyimpulkan
adanya kerusakan memori.
\end{peringatanbox}
